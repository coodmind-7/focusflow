# FocusFlow 产品分析与风险识别

## 产品理解

### 产品类型
Android 移动端专注计时应用（类似番茄钟 + 任务管理 + 统计）

### 技术栈
| 层级 | 技术 |
|------|------|
| UI | Jetpack Compose + Material 3 |
| 架构 | Clean Architecture + MVVM |
| 数据库 | Room (SQLite) + DataStore |
| DI | Hilt |
| 异步 | Kotlin Coroutines + Flow |
| 导航 | Navigation Compose |
| 序列化 | Kotlin Serialization (备份) |

### 核心功能
1. **任务驱动的计时器** — 每个任务独立计时，支持正计时和倒计时模式
2. **任务管理** — CRUD + 排序 + 颜色标签
3. **每日目标** — 可自定义的每日专注时长目标，达成时弹窗庆祝
4. **统计数据** — 日/周/月维度的环形图 + 任务分布图 + 目标达成记录
5. **数据备份** — JSON 导入/导出，支持选择性导入

### 用户旅程
```
触发 → 打开 App
准备 → 创建任务（设置名称/颜色/计时模式）
操作 → 点击播放启动计时 / 点击暂停 / 切换任务
等待 → 计时器实时更新，每日进度条推进
结果 → 停止计时 → 记录保存 → 统计页面可查看画像分析
后续 → 每日目标达成时弹窗庆祝
```

## 风险模式总结

| 风险等级 | 数量 | 关键风险 |
|---------|------|---------|
| 严重 | 3 | 竞态条件导致任务切换状态错乱、数据导入失败导致半损坏、倒计时零目标无提示 |
| 一般 | 4 | 前后台切换竞态、跨午夜日期归属错误、导入ID映射错乱、删除任务与IDLE事件时序依赖 |
| 轻微 | 3 | 输入校验缺失、空状态展示、todayTotalSeconds短暂不一致 |
| 待确认 | 1 | Room WAL模式并发写入 |

## 架构特点

### 优点
- Clean Architecture 分层清晰，UI/领域/数据边界明确
- Flow-based 响应式数据流设计合理
- 代码注释中诚实标注了已知设计限制（跨午夜问题）
- 有孤儿记录恢复机制（冷启动保护）
- 备份导入有确认对话框防止误操作

### 需关注
- ViewModel 中共享可变状态（runningRecordId、currentRecordSavedDuration、taskSessions）缺乏并发保护
- 多个协程可能同时修改同一状态变量（MutEx 缺失）
- 数据库操作未使用事务包装多步写入
- 部分用户输入缺少校验反馈
